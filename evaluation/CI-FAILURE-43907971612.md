## 4. 确认的软件缺陷：验证器没有看到研究器看到的证据

源码路径：

- `apps/dna-server-api/src/agents/tools/jev-classify.ts`：缺省 evidence 时取 cached.contentMd，即整份缓存文档。
- `apps/dna-server-api/src/news/hfs.ts`，`claimSupport`：把 evidence 直接 `.slice(0, 6000)` 后发给判断模型。

这意味着 read_item 的分页只改变 Agent 看见的窗口，**不会自动改变 jev_classify 默认 evidence 的窗口**。

从 judgment_operations.input_json.rendered.state 还原得到：五个 claim-support 操作中四个 evidence 长度正好 6000，逐字等于原文前缀；另一次 evidence 是模型显式传入的一段 158 字符引文。

实际来源里：

- `By default \`continue_run\`` 出现在偏移 10570。
- `inspect_recovery(store` 出现在偏移 48128。
- 四个默认验证请求均没有 inspect_recovery 这一段。

所以不能看到返回 unsupported 就推断“该事实不存在于原文”或“Jev 模型不会判断”。对这些后部内容，判断模型根本没有收到相关证据；158 字符那次又试图同时判断多项声明，单段只覆盖其中一项。

这是明确的输入构造缺陷，符合“先检查实际 payload，再怀疑模型”的诊断原则。不能用本次记录量化它单独造成了多少失败，也不能证明移除它就必定通过：研究器还存在范围扩张、未及时交付等独立因素。

最终 `report_findings` 的严格证据通道在 evidence.ts 中按每条有效引用与邻近上下文验证，并不是同一个全文前缀通道。但本次研究从未进入 report_findings，所以不能将该处正确设计当成前置工具没有缺陷的证据。

## 5. 其它促成因素与排除项

### 研究任务缺少预算内交付保障

研究器在两项核心事实之外核查恢复诊断、工具副作用、重试、未实现能力等扩展内容。提示中“尽量多用 Jev”与“保存 findings”存在资源竞争。即使本地曾通过，也不代表所有生成路径都能在十二次预算内交付。

不能先把预算从 12 加到更大值当作根因修复；应先减少无效验证，并为必需的 report_findings 留出执行机会。

### 重试控制及工具返回语义不足

research_items 虽在正文写出 researcher faulted，却以正常 toolText/isError=false 返回。主 Agent 在没有剩余额度的情况下再次研究，随后反复发布，产生无效恢复循环。

需要可判定的状态字段，如 completed、budget_exhausted、retryable=false，而不只给自然语言建议“再研究”。预算账应继续累计，不能重开子任务就绕过。

### 没有证据支持的解释

本次模型 generations 没有 HTTP/provider 错误，judgmentFailures=[]，12 次研究生成都是 toolUse，没有 length 截断证据。不能归因为网络 IP、密钥缺失、输出 token 截断、题库漂移或第七道空题出错。

模型行为有随机性，是一般背景，但它不足以解释已经证明的 evidence 前缀截断。也没有证据认定题面和数据本身不可解：相同冻结题在本地成功过，源文明确含要求的恢复/分叉信息。

## 6. 应修什么，以及怎样证明修好了

1. **优先修证据传递**：声明验证接受已保存 snapshot 的具体片段/引用，按声明绑定；长全文缺少定位时明确返回需要证据定位，不静默当成看过全文。维持 hash、原文与范围校验，不能允许任意生成文本冒充来源。
2. **研究预算内收敛**：先提交用户问题所需的最小事实；限制顺序全文阅读，支持 find_text；为报告提交预留机会，临近预算提醒。不要偷改本轮阈值。
3. **停止无效重试**：budget_exhausted 明确标记不可重试；研究工具返回结构化失败；主 Agent 在硬预算用尽后停止，不重启研究、不伪造 no_news。
4. **增强 CI 诊断**：门禁输出具体 taskId、失败检查、原始/复评结果及产物路径；保留严格门禁，禁止六题通过就给整套绿灯。

离线验收至少包括：五万字符来源中后部引文能准确传入 validator；缺片段/伪造 quote 被拒绝；预算不足不再启动子研究；未保存 findings 不允许发布；故障报告明确指向失败题。先重放/模拟这些工程条件，再仅对 pilot-04 做一次有预算的真实生成与复评。确认后才进行七题回归。

本次任务完成分析与取证，未改动执行逻辑、评分阈值、原始数据或远程 CI，也未启动付费重跑。
