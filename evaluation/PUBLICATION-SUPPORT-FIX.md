# 发布选材与证据状态一致性修复

2026-11-17，针对运行 43915165361 的 pilot-02 与 pilot-05。原始结果和基线不变。

**后续验收与修正**：运行 43918813378 的真实验证为 3 passed、4 failed。多个候选被新增语义发布检查反复拒绝并无交付，不能认为前置硬拦截已经可靠。v2 将该项调整为 observe，每个候选只记录一次诊断，避免生成反复修复循环；最终七题 CI、引用合法性和证据状态硬检查不变。下面关于前置拒绝的描述是 v1 实验行为，不是当前默认策略。启用 enforce 前必须补正反例及实际模型误放行/误拒校准，不能仅由 fixture 通过认定已校准。

调整后全仓类型检查、56 项免费回归通过（测试组合不含前轮的两组专项，不能把数量差异视为失败）。来源字段和已判不足的声明仍不会被自动认证为 supported。原始报告保存在 test-results/github-run-43918813378，未改分数、未追改标签。

- report_findings 保存并返回完整的最终证据状态，supported=0.85 但 sufficient=0.72 时返回 insufficient，支持计数为零；research_items 同样仅将最终 supported 状态列为可用于交付的结论。
- evidence 模式发布前增加 publication-support typed judgment：只传用户问题、当前卡片与服务端验证过的该候选声明/引用，不读取 requiredFacts 标准答案。分别检查直接回答问题、可见事实的引用覆盖；任一低于新命令冻结阈值 0.8 返回工具错误，要求改选材料/补引用/移除未支持断言。
- 待核查命题与 fact_check 的否定裁定分开理解；不允许 verifiedClaims/verificationScope 由模型自填来通过检查。不自动把另一候选的证据移植到本候选。
- 新命令进入冻结命令上下文、持久调用账及输入哈希缓存。相同卡片复用检查；改动卡片必须重新判断。旧冻结上下文缺命令时拒绝继续发布，要求新建运行。
- fixture 对新命令使用显式模拟结果，只验证工程执行；不作为语义准确率证据。生产新闻默认模式及候选数量默认值不变。
- 全仓类型检查、61 项离线回归、七题 fixture 门禁通过。新增回归覆盖错误支持计数、无效候选/缺引用的拒绝分支、服务端证据字段、修改卡片后的新判断。

发布检查本身仍是模型判断，不是形式化语义保证，需用新运行校准误放行/误拒。每次真实发布尝试增加一项 Jev 操作，计入原有请求/费用账和预算，未提升预算上限。单靠本修复不宣称七题长期全通过。
