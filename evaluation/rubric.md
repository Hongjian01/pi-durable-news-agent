# 人工标签 rubric v1

标注依据冻结 referenceTime、样本正文及明确的开发者技术情报主题，不依据 A/B/C 输出。合成工程样本只用于练习标注流程；真实质量评测须另建真实来源版本。

- `relevant`：与 Agent/大模型应用开发直接相关。体育、纯融资宣传、无技术内容的泛热点为 false；不因语种或标题夸张直接拒绝相关技术内容。
- `useful`：在 referenceTime 对目标开发者有具体可行动的新信息，例如可用版本、接口变化、迁移、安全修复或有方法说明的评测。仅传闻、无法区分的营销语、过时信息不算有用；与 relevant 分开判断并说明理由。
- `relation`：different 为不同事件；duplicate 为同一事件的实质重复；evidence 为补证/反证；development 为实质新进展（版本变化或能力更新）；uncertain 为来源不足以判断。不能把后两类一律当重复丢弃。
- `duplicateOf`：仅 duplicate 填同 split 中已出现的规范代表 sampleId，其余填 null。规范代表取该事件最早的非重复记录（时间相同按 ID 排序），避免重复链和循环；标注前统一代表清单。评测严格比较该代表，避免多代表使召回分母含糊。
- `rationale`：写明正文依据、限定条件、缺失证据及判断原因，特别解释冲突/传闻/版本差异。不以“模型认为”代替依据。

HFS 各轴独立为整数 0–4，不要求加和固定。评价正文证据和开发影响，不评价作者声望：

- hype：0 无夸张；1 少量宣传语；2 明显营销且与证据混杂；3 核心结论主要靠夸大或跨条件比较；4 耸动绝对结论且基本无支撑。高 hype 不自动等于低 relevant。
- facts：0 无可核查细节/纯传闻；1 少量具体信息但来源或条件缺失；2 有日期/版本/数值但关键方法或可用性未明；3 有明确可追溯依据及重要限定；4 关键声明逐项有直接证据且冲突被解释。来源自称的性能不能直接当独立事实。
- signal：0 无开发用途；1 泛背景/弱启发；2 对部分场景有参考价值；3 对明确工作流可行动（版本、迁移或复现条件清楚）；4 直接改变关键集成/安全/成本决策，影响范围和行动建议均有依据。

不确定性通过 relation、分轴分数和 rationale 保留。不得使用来源支持模型自评生成 gold。reviewer 独立标注后再比较；第三人裁决保留两份原标签，说明采纳依据。每个 split 至少复核 20%，语言、负例和难例均应覆盖。未来调整 rubric 必须建立新数据/协议版本，不能追着冻结测试结果改 gold。
