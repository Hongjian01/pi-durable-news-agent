# 六家机构的 Agent 评测怎样落到 AgentRadar

选取依据是任务与本项目的接近程度、评分规则能否检查，以及能否解释一个真实产品决策。国内选三家机构，含高校团队。各基准测量的对象、工具、语种和计算预算不同，无法从公开榜单推得统一的机构名次。以下是对公开体系的分析及本项目的设计决定。

### 清华 THUDM · AgentBench

AgentBench 把模型接到八类交互环境中，在多轮动作和观察之后按各环境的任务规则评分。同一模型可能会写一段正确解释，却在执行中发出无效动作、用尽轮次或得到错误状态。它提供了检查工具接口、运行环境和结束条件的方法。不同环境的综合表现难以直接外推到中文情报质量。[论文](https://arxiv.org/abs/2308.03688) · [环境与实现](https://github.com/THUDM/AgentBench)

**项目改动**：E3 从生产 workflow 启动。取证点固定为提交收据、实际工具调用、落库卡片、终态和预算账。区分启动失败、环境材料缺失、Agent 用尽预算、错误发布；同时报告全部计划任务的完成率及环境有效任务的成功率。用正确参考行为重跑环境仍无法完成的任务登记为环境错误。

### 阿里巴巴通义团队及合作者 · WebWalkerQA

WebWalkerQA 把入口网页与更深层页面的事实联系起来。一次搜索找到正确站点后，Agent 仍需导航到承载答案的页面。因此可以测出搜索结果命中而实际取证失败的情况。它更接近资料查找，不能仅凭答对一个细节给整篇研究报告打高分。[论文](https://arxiv.org/abs/2501.07572) · [团队代码库](https://github.com/Alibaba-NLP/DeepResearch)

**项目改动**：给 T10 保存入口页、链接边和目标证据页，以及在权限和预算内可达的证据集合。分别测可达任务数、实际读取正确证据页的任务比例、已取证任务的正确交付率。允许经搜索直达同一来源。用链接失效且无替代页的配对题检查证据不足时的行为。

### 红杉中国 · xbench-DeepSearch

xbench-DeepSearch 针对中文互联网设计需要规划、检索和推理的问题。项目组织专家依照出题手册制题，并用动态题池和公开、保留题并行的方式降低静态题过拟合。对本项目，中文官方文档、二手中文转述和英译中转载是三个不同的取证情境。[官方设计说明](https://xbench.org/agi/aisearch) · [首期报告](https://xbench.org/files/Leaderboard%20Report%20xbench-DeepSearch_202505.pdf)

**项目改动**：保存首发语种、证据语种、回答语种、事件组和首次曝光日期。中文检索必须有独立的中文首发切片。每个发布周期增加后续时间窗口的新事件，历史任务用于回归。本次开放给开发者的 340 条标签统一用于诊断。后续盲测从新的事件组取样。

### OpenAI · BrowseComp

BrowseComp 的问题需要持续浏览、多次尝试才能检索到具体事实，最终答案通常很短，容易核验。它将搜索难度与判分难度分开，也分析了增加浏览和采样投入带来的影响。最终答案匹配仍可能来自记忆，且无法说明答案是否有适当引用。[基准说明与论文](https://openai.com/index/browsecomp/)

**项目改动**：在 D3 每个可交付事件上预注册一个能客观判定的字段，例如迁移的参数名、最低版本或生效日期。分别计答案正确、证据支持、两者同时通过。增加只看标题摘要和可访问完整来源的配对条件，共享模型、输入与输出预算。公开 benchmark 题目不复制入库。结果揭示浏览带来的增益，不能直接推断线上用户偏好。

### Anthropic · 研究 Agent 评测与评分器校准

Anthropic 把 task、trial、grader、运行记录和最终结果分开，研究任务组合检查证据支持、覆盖及来源质量。参考输出可用于检验任务可解性；逐次审阅记录有助于发现评分器误杀或误放。其对 BrowseComp 的研究还记录了模型在开放网络上识别评测并搜索答案的情形。[工程指南](https://www.anthropic.com/research/demystifying-evals-for-ai-agents) · [评测污染实证](https://www.anthropic.com/research/eval-awareness-browsecomp)

**项目改动**：对每张卡全文抽取可核验断言，分别检查原文存在、语义蕴含、限定条件、关键事实遗漏。给评分器喂成对样例，包括同一原文支持的正确表述、明确反例和证据不足。评审时隐藏组名。单人或单模型给出的银标用于评分器开发，正式测评分器误放行率要使用独立形成的参照。

### Sierra · τ-bench

τ-bench 让模拟用户与能调用业务工具的 Agent 多轮交互，用会话结束后的数据库状态与目标状态比对，再用 pass^k 衡量同一任务多次均成功的可靠性。终态判断减少了对固定措辞、固定工具顺序的依赖。数据库单独无法验证卡片中的自然语言，也可能漏掉中途发生后被撤回的副作用。[机构说明](https://sierra.ai/resources/research/tau-bench) · [论文](https://arxiv.org/abs/2406.12045)

**项目改动**：E3 为每任务声明允许变化的状态和必须保持的状态。发布检查卡片唯一性、规范事件、来源绑定及全过程副作用。三次重复均从相同库独立开始，用三次都通过的任务数除以完成预定试验的任务数，并单列未完成任务；同时给出以全体计划任务为分母的保守结果。

### 如何判定一次改造有效

举例，用户要求报告某 SDK 迁移步骤。官方发布页能打开，但参数名只出现在迁移页。若 Agent 抄对参数却引错页面，短答案得分为 1，证据得分为 0，业务任务失败。若迁移页取得且引用正确，却在恢复后发布两张相同卡片，内容得分保留，终态失败。若入口页和迁移页在冻结时均无法访问且任务仍要求必答，先修数据再运行。三种情况有相同的任务失败标志，却对应三种不同修复。

主实验以同一任务三组配对。预先固定 K、可访问来源、任务级成功规则和可接受成本。E2 的实际研究条数较少仅证明工作量变化；只有费用账、合格交付数、配对区间均满足主协议时，才给出成本收益结论。
