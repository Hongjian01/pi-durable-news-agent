## 1. 确认产品验收偏好

填写目标读者、主要关注主题、单轮研究预算、可接受延迟、漏报与噪声的相对代价。当前默认是 Agent/LLM 应用开发者，沿用现有产品偏好。现有质量门槛仍是开发阶段目标，尚需负责人在正式留出实验前确认。

可在网页“偏好设置”调整日常使用的主题和来源。正式实验通过固定协议记录这些参数，避免与个人运行设置相互影响。

## 2. 配置真实实验账户与预算

已补充[密钥、模型与 SQLite 配置步骤](ACCOUNT-SETUP.md)。主 Agent 与研究模型已支持 DeepSeek 官方直连：配置 DEEPSEEK_API_KEY，并使用 --provider deepseek。Jev 与可选语义评分器仍使用 OPENROUTER_API_KEY。SQLite 数据库由程序自动建立。

在 WSL shell 或密钥管理工具设置 OPENROUTER_API_KEY，选择 DNA_MODEL、DNA_RESEARCH_MODEL 和独立 judgeModel，并确定一次实验愿意承担的美元额度。CLI 使用 --enable-paid 明确启用真实调用。

当前实现支持供应商强制执行的专用额度，包括覆盖 BYOK、无周期重置、剩余额度在 --max-usd 以内的密钥额度或等价预算。请在供应商账户中配置额度。程序能检查额度并执行请求，账户设置与付款由账户持有人操作。

上述 --max-usd 核验仅覆盖 OpenRouter 侧费用。DeepSeek 官方直连在另一账户结算，需要单独控制余额或消费限额；DNA_COST_ALERT_USD 为告警阈值。

首次用 pilot-03 单题实测，再决定是否运行全部任务。正式报告中需保留供应商解析型号、用量、已知费用及未知费用。真实模型、Jev 和评分器调用均会消耗额度。

## 3. 组织独立复核

当前标签、参考答案和评分器样例由 Codex 辅助准备，humanReviewed 为 0。独立复核可由你或具备相关知识的同事完成。

先核查六个取证题的原文与关键事实。优先检查版本、草稿/正式发布、工具权限、恢复保证等易误读条件。使用 eval:capture 生成的 review-queue.jsonl 填写 reviewer、origin、at、decision 和 rationale。真实人员记录自己的判断；后续自动校验可以检查格式、引文和一致性。

若只有一名复核者，就如实报告单人复核。独立人工一致率需要至少两人先分别提交再比对。复核前隐藏模型输出和其他人的标签。

## 4. 提供真实使用反馈

在实际扫描中记录被漏掉的重要事件、重复推送、错误事实和不合适的推荐。每条反馈尽量包含扫描或卡片编号、错误说明以及正确来源。

至少选一个重要失败案例，核实后进入回归集。开发者可调整策略并运行新旧版本比较。你或目标用户确认发布后是否改善了使用体验。

## 5. 正式发布与外部结论

准备上线或对外展示时，确认正式留出集、验收门槛、费用口径和标签来源。对模拟后端与银标的实验，使用开发诊断表述。对真实模型的结果附任务数、重复次数、误判与区间。

GitHub Actions 已提供工作流文件。将代码提交到你使用的远程仓库后，查看该仓库中的实际 CI 执行情况。远程推送、密钥配置和正式发布按你的授权执行。
